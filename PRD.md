# Overview
I want to build an Android mobile app that will allow Scouting America scouts to track and record their progress in earning merit badges. 

# Key User Journeys
- On first app launch the user should be prompted for their name and unit number.
- The user should be able to change their name and unit number later.
- On subsequent app launches the user should land on a home page that displays their name and a summary of their merit badge progress.
- A user should be able to browse a list of all current Scouting America merit badges.
- A user should be able to search for a specific merit badge by name or description.
- When a merit badge is selected the user should be given a page that briefly describes the merit badge and allows the user to record their progress towards completion.
  - This page should begin with a brief description of the merit badge and any relevant information, such as whether it is eagle required.
  - This page should give the user the ability to enter their merit badge counselor's name and contact information.
  - This page should give the user a brief description of each requirement for the merit badge as well as the ability to record all relevant data necessary to satisfy the progress against that requirement.
  - This page should be easy to navigate on a mobile device, and the user should be able to understand the full set of requirements without extensive scrolling. If any part of the merit badge requires large trackers or detailed information the user should have the option to click into a sub-page for those requirements.
  - Where possible, the brief descriptions of requirements should link to the full, official, Scouting America documentation for the relevant requirement.
  - When recording progress on a merit badge requirement the user should have the option to include a date on which the requirement was completed.
  - When recording progress on a merit badge the user should have the option to add notes about that requirement.
  - When a merit badge is completed the user should have the ability to generate a report in PDF format that reflects the entirety of the data they have recorded for that merit badge, and to save and/or share that report with standard Android save and share features.
  - This page should allow the user to mark a merit badge as completed on a prior date without entering specific data for each requirement.
  - Scouting America updates merit badge requirements over time, usually each January 1. By default, a merit badge should use the newest version of its requirements.
  - The user should be able to select the previous version of a merit badge's requirements instead, when the app has one, for example if they started working on the badge before a change.
  - The first release of the app includes only each merit badge's current requirements. From then on, the app keeps every version of the requirements it has shipped, so existing users can keep working on the version they started.
  - When an app update brings newer requirements for a merit badge the user has already started, the badge should stay on the version the user was using, so their recorded progress still matches its requirements. The user should be able to switch that badge to the newest version themselves.
- A user should be able to track and record their progress toward each Scouts BSA rank, Scout through Eagle, as they do for merit badges.
  - When recording progress on a rank requirement the user should have the option to record who signed off on it, in addition to notes.
- A user should have the option to clear all merit badge data, all progress for a specific merit badge, or specific progress information for a particular merit badge.
- A user should have the option to export their merit badge data, as well as import previously exported data.

# Other Requirements
- All data will be stored locally on the mobile device. There is no cloud syncing of data.

# Design decisions
Choices about how the app looks and behaves, made while building it, and why. Technical decisions are in [`ARCHITECTURE.md`](ARCHITECTURE.md#decisions).

| Decision | Choice | Why |
|---|---|---|
| Badge search | Every word of the search must start a word in the badge's name or summary, in any order, ignoring case | Finds a badge from the start of any word ("fit" finds Personal Fitness) without matching inside words, so a short search like "art" isn't flooded with summaries that say "part" or "start" |
| Search result announcements | A line under the search field says how many badges match. Screen readers hear it when it changes, once typing pauses or straight away after Clear search, but not as Badges appears | Spoken on every keystroke, it held back TalkBack's echo of each key, and read as Badges opened, it held back the heading ([#71](https://github.com/bryancassell/bluecard/issues/71), [#278](https://github.com/bryancassell/bluecard/issues/278)) |
| Search on a short window | When Badges is too short for its heading, search field and count, as in landscape with the keyboard open, the heading is left out and the field and count move to the top | The field and what's typed in it matter more than the heading: with it, landscape left the field a strip that hid the text ([#308](https://github.com/bryancassell/bluecard/issues/308)) |
| Failure message announcements | Screen readers hear a message that takes a page's place, such as "Couldn't load your data…", as it appears, and every "Couldn't save. Try again." snackbar ([#234](https://github.com/bryancassell/bluecard/issues/234)) | Otherwise TalkBack read it only if its focus moved onto it, so with its focus on a heading that stays, nothing told the scout ([#69](https://github.com/bryancassell/bluecard/issues/69)) |
| Requirement completed for the scout | Screen readers aren't told when a requirement becomes complete, or stops being, without the scout ticking it, as when its tracker's last row is saved. TalkBack reads "Completed" on its page and row | That's where a sighted scout sees it, and Android [asks](https://developer.android.com/about/versions/16/behavior-changes-all) that live regions be "used sparingly" ([#109](https://github.com/bryancassell/bluecard/issues/109)) |
| Eagle-required progress | Home counts each Eagle "one of" group, such as Cycling, Hiking and Swimming, once, with the status of its furthest-along badge | Earning any badge in the group meets the requirement |
| Badge progress bar | While a badge is in progress, a bar under its name shows how much is done, with "In progress" at the row's end (Status in a narrow row), and screen readers hear "40% done". Each top-level requirement counts the same, and within one, each part it needs, such as a tracker's rows (Rows a log needs, Tracker totals) | "In progress" alone didn't tell a badge just started from one nearly done ([#159](https://github.com/bryancassell/bluecard/issues/159)) |
| Status in a narrow row | A status at a row's end, such as "In progress", goes on a line of its own under the row's text wherever a word beside it would break, as at the largest text and display size | Squeezed, words broke in the middle, such as "Swimmi" / "ng" ([#307](https://github.com/bryancassell/bluecard/issues/307)). Moving it only then keeps rows as they were at the default sizes |
| Requirement list | Badge detail lists only the top-level requirements, each with its number, our one-line summary, "Do N of M" when only some sub-requirements are needed, and progress such as "8 of 12 weeks" (Rows a log needs, Tracker totals, Merit badge requirements). Each opens a page listing its sub-requirements the same way | Requirements stay understandable "without extensive scrolling": each page shows one level of the requirement tree |
| Marking a requirement complete | A "Completed" checkbox on the requirement's page, dated today or earlier, with notes; rows only open the page. A requirement with sub-requirements has no checkbox unless it asks for work of its own (below), as enough of them complete it | Chosen after using the app, over a checkbox on each row ([#103](https://github.com/bryancassell/bluecard/issues/103)), though marking many parts then takes a trip to each page |
| Date picker on a short window | On a window too short for the whole date picker, as in landscape, the picker scrolls, header included, so every day is whole and full size. It opens at the top, on the calendar where that fits (Date picker on a narrow window) | Material clipped the month's first and last weeks to fit, leaving days too small to tap or hidden ([#282](https://github.com/bryancassell/bluecard/issues/282)) |
| Date picker on a narrow window | On a window narrower than the calendar, as at the largest display size, the picker is for typing the date, with the keyboard down until the scout taps the field | Material's dialog doesn't shrink, so its last days and OK were off the screen ([#306](https://github.com/bryancassell/bluecard/issues/306)). The largest display size is chosen by those who most need big touch targets |
| Date picker's buttons | Cancel, then OK, at the end of a row below the picker. If they don't fit side by side, OK goes below Cancel | They're read and focused in the same order either way, unlike Material's dialogs, which put OK above Cancel |
| A date's buttons | Change date and Remove date sit side by side under a date, as do Change date and Unmark in the status card. If they don't fit, as at the largest text and display size, the second goes under the first | Squeezed into one row, Unmark broke to "Unmar" / "k" ([#307](https://github.com/bryancassell/bluecard/issues/307)). Stacked, they're read and focused in the same order, as the date picker's are |
| A requirement's own work | When a requirement with sub-requirements or a fixed-row tracker also asks for work of its own, such as Space Exploration 3's rocket launches, its page has a checkbox for that work, labeled with our summary of it. The requirement is complete once that's checked and enough sub-requirements are, or every row is filled in | Sub-requirements or rows alone completed requirements whose main work or closing step wasn't done ([#143](https://github.com/bryancassell/bluecard/issues/143), [#229](https://github.com/bryancassell/bluecard/issues/229)) |
| Showing whether a requirement is complete | The row's number sits in a box: outlined while nothing of it is done, tinted with a half circle on its corner once part of it is, and filled in Scouting America Blue with a check once complete. It's grey, with "Not needed", once its parent has enough without it | A small check beside the chevron was easy to miss ([#123](https://github.com/bryancassell/bluecard/issues/123)), and a requirement looked untouched until all of it was done ([#158](https://github.com/bryancassell/bluecard/issues/158)). The half circle shows the tint by shape, not color alone |
| Counting complete sub-requirements | A tinted row says how many of the sub-requirements it needs are complete, such as "Do 2 of 3 (1 of 2 complete)". When only its own work is left, a line under the count says what, in full: "Still to do: Clean and adjust a bike…" | It says how close the requirement is ([#158](https://github.com/bryancassell/bluecard/issues/158)). With only its own work left, "(6 of 6 complete)" read as finished ([#167](https://github.com/bryancassell/bluecard/issues/167)) |
| Unchecking a requirement | Removes its date and keeps its notes. The page remembers the date until it closes or the requirement is cleared, and checking the requirement again there brings the date back | A mistaken tap loses nothing, while stored progress stays simple: a requirement that isn't complete has no date |
| Starting a badge | Recording anything starts it, dated today; it stays started after everything is undone, until the scout clears it | No extra step before recording; clearing a badge is its own action ([#45](https://github.com/bryancassell/bluecard/issues/45)) |
| Ranks | A Ranks button on Home opens the seven ranks in order, in Badges' rows with "Earned" for "Completed", and each opens Rank detail, laid out as Badge detail, with its report once earned (PDF report). Only the lowest rank not earned is "In progress", and a rank is earned only once the one below it is | Ranks are earned in order, so only one is next, though the scout can record any rank's requirements ([#193](https://github.com/bryancassell/bluecard/issues/193)). Scouts say a rank is earned |
| Rank requirement groups | Lettered rank requirements with no number above them in the official PDFs, such as Scout 1a–1f, are grouped under that number, with our summary of them. The group is complete once they all are, and has "Signed off by" and notes | Each page shows one level, as for badges (Requirement list), so Tenderfoot lists 11 rows rather than 27 ([#286](https://github.com/bryancassell/bluecard/issues/286)). A leader often signs off the group at once |
| Rank on Home | First on Home, a card in the primary color shows the scout's rank, a trail of dots for the seven ranks, and the next rank, which tapping it opens. Screen readers hear one heading, with "2 of 7 ranks earned" for the trail | Rank is the scout's main standing ([#193](https://github.com/bryancassell/bluecard/issues/193)). As a row, the rank in progress read as one more badge in progress; the color sets it apart, and the trail shows ranks are earned in order ([#231](https://github.com/bryancassell/bluecard/issues/231)) |
| Marking a rank earned on a prior date | As for a badge (below), with Mark earned. Marking a rank counts every rank below it as earned, without a date ("Counted as earned with Life", with Add date), and unmarking undoes that | A scout who starts using BlueCard as a Life Scout marks only Life ([#193](https://github.com/bryancassell/bluecard/issues/193)). Add date gives a lower rank a date for time in rank to count from |
| Time in rank | Star 1 and 5, Life 1 and 5, and Eagle 1 and 4 ask for months in the rank below. Their page says when the scout is eligible, such as "Eligible from Jan 1, 2027, 4 months after earning First Class", but they can check it off any time | The date is only a guide: a position of responsibility taken later, or on Star 5 and Life 5 a leadership project, changes it ([#193](https://github.com/bryancassell/bluecard/issues/193)) |
| Merit badge requirements | Star 3, Life 3 and Eagle 3 are complete once the scout has completed enough merit badges and enough Eagle-required ones, marked badges included, with Eagle 3 counting an Eagle "one of" group once. The row shows "4 of 6 merit badges" and "2 of 4 Eagle-required", and the page lists the badges and what's still needed, such as "Needs 3 more merit badges, 2 of them Eagle-required" | Counting from badge progress, the scout records each badge once ([#193](https://github.com/bryancassell/bluecard/issues/193)). The counts alone can mislead: with 5 of 6 badges but 2 of 4 Eagle-required, one more badge won't do |
| Marking a badge completed on a prior date | Mark completed in the status card (below) opens the date picker, then the card shows "Completed on <date>" with Change date and Unmark, which asks nothing: the picker then opens at the date just unmarked. What's recorded stays, and a requirement still needed with nothing done reads "Not recorded" in place of "Not completed" | Lets a scout count badges earned before using BlueCard without entering each requirement ([#41](https://github.com/bryancassell/bluecard/issues/41)). Remembering the date makes a mistaken Unmark cheap without a dialog |
| Status card | On Badge detail and Rank detail, a card under the official link says where the badge or rank stands, in Badges' and Ranks' words, with what the scout can do: Mark completed or Mark earned, or once done, the date's buttons and the report buttons. A complete rank waiting on the one below says so | As text buttons, Mark completed and Mark earned read as captions and were easy to miss ([#247](https://github.com/bryancassell/bluecard/issues/247)). A complete rank's full bar didn't say why it wasn't earned ([#211](https://github.com/bryancassell/bluecard/pull/211)) |
| Trackers | Listed on the requirement's page, each row filled in on its own page, with multi-line fields for description and list columns: a log numbers its rows as added ("Session 3"), and a fixed-row tracker shows every row ("Week 1" to "Week 12"). Screen readers hear a date's buttons with the column's name: "Add date: Week starting" | Four or more fields don't fit in a dialog or table row once the keyboard is up. A one-line field hid most of a description ([#168](https://github.com/bryancassell/bluecard/issues/168)), and screen readers missed the column's name ([#166](https://github.com/bryancassell/bluecard/issues/166)) |
| Save while typing in a tracker row | While the scout types in a row's last field, the page scrolls to keep it and Save above the keyboard, unless the field is too tall for both or the scout has scrolled away | Save sat partly behind the keyboard once the last field could take more than one line ([#172](https://github.com/bryancassell/bluecard/issues/172)). The line being typed, and where the scout chose to look, matter more than Save |
| Moving between a tracker row's fields | The keyboard's Next moves to the next text field, and a one-line last field has Done; a multi-line field keeps Enter. On an on-screen keyboard, Next skips a date's buttons, and the scout taps "Add date" when ready | The scout had to tap each field ([#182](https://github.com/bryancassell/bluecard/issues/182)). Going to the date's button would have closed the keyboard |
| Completing a fixed-row tracker's requirement | Complete once every row is saved, even with empty fields, with no checkbox, unless it has own work (A requirement's own work). Its date is when the last row was first saved, which the scout can change or remove | Its rows are its parts, like sub-requirements ([#105](https://github.com/bryancassell/bluecard/issues/105)). Rows copied from a paper log dated it the day they were typed ([#116](https://github.com/bryancassell/bluecard/issues/116)) |
| Tracker totals | A log whose requirement asks for an amount, such as Star 4's 6 hours of service, adds that column up against it: "4.5 of 6 hours". It fills the progress bar and says what's still to do, as for Rows a log needs | The scout sees how far along they are without adding up the rows ([#193](https://github.com/bryancassell/bluecard/issues/193)), and the bar moves with them ([#292](https://github.com/bryancassell/bluecard/issues/292)). The requirement can ask for more than the amount, such as Life 4's approved projects |
| Rows a log needs | A log whose requirement asks for a number of rows, such as Second Class 4's at least 10 kinds of wild animals, counts them ("6 of 10 animals"), and each row, like checking it off, fills the progress bar. Once the rows reach the number, a line says to check it off | Logs let the scout record more than N, but read "6 animals" and added nothing to the bar ([#284](https://github.com/bryancassell/bluecard/issues/284)). "30 of 30 days" beside an unchecked box read as finished ([#293](https://github.com/bryancassell/bluecard/issues/293)) |
| Requirement notes | On every requirement, including one with sub-requirements, saved with a Save button | The scout decides when notes are saved, and a save that fails is reported right then, not while they're still typing |
| Save while typing in a requirement's notes | While the scout types in the notes, they and Save stay above the keyboard, as a tracker row's last field and Save do. Clear progress, under Save, can stay behind it | Save notes sat partly behind the keyboard on a phone ([#178](https://github.com/bryancassell/bluecard/issues/178)). Clear progress isn't part of saving what the scout types |
| Signed off by | A rank's requirement has a one-line "Signed off by" field above its notes, saved with them and shown in the PDF report, but it doesn't complete the requirement. A merit badge's requirement has none | A leader signs off each rank requirement, and the notes were the only place to say who ([#248](https://github.com/bryancassell/bluecard/issues/248)). A badge's counselor is recorded once, on Badge detail |
| Counselor details | Shown on Badge detail above the requirements, and edited on a page of their own whose Save closes it once the save succeeds. Tapping the phone or email opens the phone or email app, with no format check | Entered once and read often, so Badge detail stays short. Closing only after a successful save shows a failure while the scout can still try again |
| Unsaved changes on Back | Back asks "Discard changes?" first on a page whose fields differ from what's saved: Tracker entry, a requirement's notes, Edit counselor, and Edit name and unit. Discard closes the page without saving | Back discarded edits with no warning ([#99](https://github.com/bryancassell/bluecard/issues/99)). Saving instead would close the page before a failed save could be reported, and leave no way to throw an edit away |
| Clearing a requirement | A "Clear progress" button at the bottom of its page, once anything is recorded for it or a requirement under it. It clears them all, and the badge stays started | The scout reads a requirement as including its sub-requirements. Clearing one can un-earn ranks its page doesn't show ([#219](https://github.com/bryancassell/bluecard/issues/219)) |
| Clearing a badge | A "Clear progress" button at the bottom of Badge detail, once the badge is started, clears everything recorded, counselor included, so the badge is no longer started. Unmarking a badge, or unchecking a requirement, asks nothing | It's the only way back to not started. Star, Life and Eagle count completed badges, so clearing one can un-earn them ([#219](https://github.com/bryancassell/bluecard/issues/219)). The page remembers what an unmark undid |
| Clearing a rank | As for a badge. Unmarking a rank asks nothing, and the page remembers the date | Ranks are earned in order, so clearing one can un-earn others its page doesn't show ([#211](https://github.com/bryancassell/bluecard/pull/211)) |
| Unsaved notes when clearing | Clear progress also discards an unsaved edit of the notes or sign-off once the clear is saved, and its dialog warns first. A clear that fails keeps the edit | Decided after [#133](https://github.com/bryancassell/bluecard/pull/133), where an unsaved edit survived a clear: discarding it made the most sense ([#137](https://github.com/bryancassell/bluecard/pull/137)) |
| Confirming a removal | Deleting a tracker row, clearing progress and discarding unsaved changes ask first, in one shared dialog that names any ranks the removal would un-earn. Its confirm button is red, as are the Delete and Clear progress buttons | Red marks the button that removes what the scout recorded, which can't be undone. A removal can un-earn ranks the page doesn't show ([#259](https://github.com/bryancassell/bluecard/issues/259)) |
| PDF report | "Share report" and "Save report" in the status card once a badge is complete or a rank earned. US Letter pages with the scout, the badge or rank, and every requirement with what was recorded, done or not, and on Star 3, Life 3 and Eagle 3 every badge completed | A counselor reading it sees the whole badge. A rank is offered its report once it's earned, as a badge once it's complete ([#193](https://github.com/bryancassell/bluecard/issues/193)) |
| Changing the name and unit number | A "Name and unit" section, first on Data management, whose Edit button screen readers hear as "Edit name and unit". It opens a page like the counselor's, with both fields still required | Changed rarely, so Home stays as it is ([#160](https://github.com/bryancassell/bluecard/issues/160)). A screen reader user moving between controls doesn't hear the heading ([#166](https://github.com/bryancassell/bluecard/issues/166)) |
| Export | Export on Data management saves the name, unit number and all progress to one file where the scout chooses, with the system file picker. It suggests a name with the date, such as "BlueCard export 2026-10-01.json" | The date tells exports apart, and they sort by it. The file picker lets the scout keep it on the phone or in a cloud drive, without storage permissions |
| Import | Once the file is checked, a dialog asks whether to merge it with the phone's data (Merging an import) or replace all of it, in red. A file that isn't an export, or is from a newer app, gets a message saying so | Replacing everything stays for a scout moving to a new phone ([#28](https://github.com/bryancassell/bluecard/issues/28)). Checking first means the scout is never asked about a file that can't be imported ([#46](https://github.com/bryancassell/bluecard/issues/46)) |
| Merging an import | Badges and ranks started on only one side are kept, and each comes whole from one side. Where both started one with different progress, or the name or unit number differ, a full-screen dialog asks which to keep, starting on the phone's, with how far each got | The export doesn't record when anything changed, so the app can't tell which side is newer, and the scout decides ([#28](https://github.com/bryancassell/bluecard/issues/28)) |
| Clearing all progress | A "Clear all progress" section, last on Data management, with a red "Clear all" button, disabled until a badge or rank is started. It asks first, then clears all progress, counselors included, but keeps the name and unit number | Last and red, so it isn't tapped by mistake. Disabled rather than hidden, so the scout can see where it lives. A message confirms it ([#45](https://github.com/bryancassell/bluecard/issues/45)) |
| Damaged progress | When the progress saved on the phone is found damaged, BlueCard starts over without it and says so in a dialog, which says the name and unit number are kept and an export can be imported. It shows at each launch until the scout taps OK | A scout's records may cover years of work, so they're never lost without the scout knowing ([#70](https://github.com/bryancassell/bluecard/issues/70)) |
| Switching requirement versions | Starts the badge's requirement progress fresh, after a confirmation; counselor details stay | Requirement numbers can mean different things in different versions, so entries aren't attached to the wrong requirement; carrying progress over is tracked in [#29](https://github.com/bryancassell/bluecard/issues/29) |
| Requirement changes | Shipped with regular app updates, with no urgency or monitoring process | The app doesn't need to reflect Scouting America's changes immediately. Scouts who already started may keep the previous requirements anyway. Until an update ships, a scout starting a changed badge sees the previous requirements in the app; the linked official page has the current ones |
| Page transitions | Pages slide the full width of the screen, side by side, in 375 ms, and Onboarding and the rest of the app crossfade. A released back swipe does what Back does, without moving the pages first | Navigation 3's defaults looked strange, and the platform's shorter slides, which Material 3 advises, felt too short on a Pixel 9 ([#104](https://github.com/bryancassell/bluecard/issues/104)) |
| Focus when the page changes | Opening a page, or going back to one, never puts input focus on one of its items, so the keyboard stays closed and TalkBack starts where it does when the page first opens. Tab or an arrow key moves into the page | After a key press, reopening Badges opened the keyboard and moved TalkBack to the search field ([#285](https://github.com/bryancassell/bluecard/issues/285)). Searching is the scout's choice, not where Badges starts |
| Focus after Save, or a button that goes | Saving leaves nothing on the page with input focus, nor does a button pressed with a key that goes or is disabled as it's used, such as Unmark, so Tab or an arrow key then moves into the page. On a requirement's page, which stays open, TalkBack stays on Save | With a hardware keyboard, Save and Unmark moved focus to the page's first item, so the scout lost their place ([#297](https://github.com/bryancassell/bluecard/issues/297), [#301](https://github.com/bryancassell/bluecard/issues/301)) |
| Colors | The merit badge blue card's colors on every phone, none from the wallpaper, with every text color meeting WCAG AA. Dark mode puts Dark Blue (`#003366`) cards on a darker blue page, with Pale Blue (`#9AB3D5`) for Scouting America Blue | The app takes its look from the blue card, and dark mode darkens it rather than showing a bright page ([#108](https://github.com/bryancassell/bluecard/issues/108)). Readability comes before matching the card |
| Status bar | Every page has a band behind the status bar, a little darker than the page (`#DFE6F3`; lighter in dark mode), shown all the time. The full-screen Merge dialog has none: its status bar is its top row's color | A page scrolled up to the bar ended right under the clock, and at the largest text size ran into it ([#315](https://github.com/bryancassell/bluecard/issues/315)). The color is Material's for a top app bar a page has scrolled under |
| Links to scouting.org | Link each badge to its official page, and each rank to its requirements PDF. Eagle Scout links to the PDF of all the ranks | The PRD asks for links. scouting.org has no page for each rank, and Eagle has no PDF of its own |
